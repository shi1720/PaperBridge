# PaperBridge implementation contract

React SPA + Firebase Authentication, Firestore, Storage, callable Cloud Function `api` (us-central1). All application writes pass through authenticated callable or HTTP handlers. Manuscript and media bytes use authenticated HTTP upload endpoints with server-chosen immutable Storage paths; direct client Storage writes are denied. All dates numeric milliseconds. All records return id.
Callable payload {action, ...fields}. Read calls via api for simplicity; return {data: value}. Client function call(action,payload) unwraps .data.data.
Profiles: id,name,role(researcher|endorser),headline,institution,bio,categories:string[],acceptingRequests:boolean,weeklyCapacity:number,arxivUrl,orcid,publicProfile:boolean. email only private users doc. Public profiles in profiles.
Papers: id,ownerId,title,abstract,category,authors,storagePath,fileName,text,visibility(private|public),createdAt,updatedAt. Manuscripts private by default; paper list owner only. API paper.get checks owner or participating reviewer.
Requests: id,paperId,title,category,requesterId,reviewerId,requesterName,reviewerName,message,endorsementUrl,status(pending|reviewing|changes_requested|accepted|declined|withdrawn|endorsed),createdAt,updatedAt. accepted means willing, endorsed is manually confirmed external completion. No automatic official verification.
Actions: profile.save{profile}, profile.get{id?}, directory.list{category?,search?}, paper.save{paper},paper.list{},paper.get{id},paper.delete{id}, request.create{paperId,reviewerId,message,endorsementUrl},request.list{},request.get{id},request.status{id,status,note?},request.messages{id},request.comment{id,body}, annotation.list{paperId},annotation.save{paperId,page,quote,body,color,visibility(private|shared),rects?},annotation.delete{id},feed.list{},feed.post{body,paperId?,arxivUrl?},feed.like{id},feed.comments{id},feed.comment{id,body},feed.delete{id},follow.toggle{id},follow.list{},chat.list{},chat.open{userId},chat.messages{id},chat.send{id,body},notifications.list{},notifications.read{},leaderboard.list{period:week|all},account.export{},account.delete{},report.create{targetId,reason},block.toggle{userId}.
AI: the callable delegates ai.* actions to functions/src/ai.ts inside the account-operation lease. Key settings return metadata only; provider credentials are encrypted at rest with a server secret and bound to the user/provider. Each job requires explicit manuscript/metadata consent. Dynamic catalogs configure five specialists (evidence, originality, methods, formatting, reviewer) with per-specialist provider/model and supported reasoning effort; synthesis follows those stages. Partial coverage, measured PDF extraction limits, rejected ungrounded findings, provider usage and stage failures remain visible.
No fake members on production. The interactive fixture is development-only, with a clear demo banner and in-memory records; production builds ignore demo query parameters. Production empty states invite genuine participants.

Revision extension: Papers return version (legacy default1) and versions (latest20 metadata entries including current). paper.save accepts expectedVersion to reject stale writes; storagePath/text changes increment revision, metadata-only changes do not. Active requests lock category. paper.version.get{id,version} returns selected PDF metadata/downloadUrl plus currentVersion; owner/active reviewer only, even for public papers. Notes include paperVersion (legacy1); annotation.save accepts expected paperVersion and rejects stale revision, archived notes are read-only except deletion. Active request updates expose paperVersion,currentPaperTitle,paperUpdatedAt,revisionAvailable while preserving initial title and status.

List DTOs: paper.list omits text and versions; supplies textCharacterCount (legacy-compatible) and version. paper.get retains full owner/authorized manuscript data. ai.jobs returns only id,ownerId,paperId,title,status,createdAt,updatedAt; ai.job.get retains the full private audit report.

Community/media extension: HTTP paperbridgeUploadMedia POST raw bytes ?purpose=avatar|community&fileName=... returns data{id,purpose,kind,fileName,size,contentType,width,height,url,expiresAt}. Avatar5MiB/image8MiB/PDF20MiB; JPEG/PNG/WebP normalize to WebP; max4 mixed community attachments. media.get{id},media.remove{id}; profile.save profile.avatarId omitted preserves/null removes; profile DTO avatarUrl. feed.post/edit{id?,body?,postType?,mediaIds?,paperId?,arxivUrl?,visibility?}; postType update|question|paper|milestone, edit omissions preserve prior values; visibility public(default)|private. feed.save{id}->saved boolean; feed.list saved/authorId/following mutually exclusive. Post attachments are authorized media DTOs; authorAvatarUrl,saved,liked included. chat.list/open avatarUrls map; feed.comments authorAvatarUrl.

Scoped collaboration extension: annotation.list{paperId,requestId?}; annotation.save accepts requestId immutable after creation and preserves replies/resolution on edit. annotation.reply{id,body}; annotation.resolve{id,resolved}. DTO adds authorName,requestId,replies[{id,authorId,authorName,body,createdAt}],resolved,resolvedBy,resolvedByName,resolvedAt. Shared request notes require that exact active participant pair; private notes require author. Archived notes reject edits/replies/resolution. request.get adds requesterAvatarUrl/reviewerAvatarUrl and request.messages adds authorAvatarUrl. Full details/limits in docs/backend.md.

Social activity extension: notifications.read{id?} marks one owned notification, or all existing unread notifications when id is omitted; new arrivals after the read cutoff are preserved. notifications.list returns up to 200 newest items. Follows and likes create one renewable notification per actor/target rather than one permanent item per toggle. Scoped shared-note creation, replies and resolution changes notify the other request participant; private drafts remain silent.

chat.list/open return caller-only unreadCount and lastReadAt plus lastMessageAt/lastMessageAuthorId. chat.read{id,through?} advances the caller's read position through the last rendered message timestamp; omitted through uses the latest message. It returns {unreadCount,lastReadAt,updated}, where updated counts matching message alerts marked read. Read positions never move backward, unrelated alerts and later messages remain unread, and other members' read-state maps are not exposed. Sends atomically recheck membership, blocks and recipient deletion, then update the message, unread count and alert. Old conversations derive their initial unread count from retained history.

Feed visibility is applied while filling each page. Set includePageInfo:true to receive {posts,nextCursor,hasMore}; nextCursor is {createdAt,id} or null and is sent back as cursor. Each query stream scans at most 200 raw posts (up to ten streams for the 300-follow cap). A hidden-content scan may return zero posts with hasMore:true; clients must preserve the continuation rather than show an end-of-history claim. Stream frontiers preserve descending createdAt/document-id ordering without skipping or repeating posts. Legacy callers still receive arrays.
